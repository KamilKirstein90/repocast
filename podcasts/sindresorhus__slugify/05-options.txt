Last episode we followed a string through the full slugify pipeline. Today we look at the knobs you can turn, and more importantly, the real situations where you'd want to turn them.

Let's start with the separator. By default it's a dash, which is what you want for URLs. But maybe you're generating filenames or database keys and prefer underscores. Just pass an underscore as the separator. You can even pass an empty string, and "BAR and baz" becomes barandbaz with nothing in between. Multi character separators work too, like two underscores, because the code escapes the separator before using it in a regular expression, and the cleanup step collapses runs of it correctly.

Next, lowercase. It's on by default. If you turn it off, the casing survives, so "Déjà Vu" becomes Deja dash Vu with capital letters. Under the hood, turning it off simply adds uppercase A to Z to the set of characters allowed in the slug.

Then decamelize, also on by default. That's the feature that turns fooBar into foo dash bar. If your input is regular prose, it's harmless. But if you're slugifying brand names or identifiers where you want the camel case to melt together, turn it off and fooBar becomes foobar.

Custom replacements is probably the most useful option. You pass a list of pairs, each with a string to find and a string to put in its place. These run before everything else, during the transliteration step. A neat trick from the readme: if you want the replacement to become its own word in the slug, put a space before and after it. Replacing the at sign with plain "at" turns foo at unicorn into fooatunicorn, but replacing it with "at" surrounded by spaces gives foo dash at dash unicorn. Your replacements are merged with the three built in ones, and if you use the same key, like the ampersand, yours wins. One test shows how you could force German style umlaut handling with replacements, turning Zürich into zuerich.

Now the two preserve flags. Preserve leading underscore keeps a single underscore at the start if the input began with one. The readme mentions filenames for hidden paths on a website as a use case. Preserve trailing dash keeps a dash at the end if the input ended with one. That one is designed for live input fields: imagine a user typing a slug character by character. Without this option, the moment they type a dash it would be stripped, and they'd never be able to type the next word. With it, the dash stays put while they type.

Preserve characters lets you whitelist specific characters, such as a hash sign if you're slugifying something with a URL fragment, or a dot. There's one rule: you can't preserve the separator itself, because then the cleanup logic couldn't tell real separators from preserved characters. If you try, slugify throws an error with a clear message. Also note that the apostrophe in contractions is still removed even if you preserve the apostrophe, because contraction handling runs first.

The locale option is passed through to the transliterate package and is also used for lowercasing. The classic example is the Swedish word for a shrimp sandwich, Räksmörgås. By default, the ä and ö are transliterated German style into a e and o e. With the locale set to Swedish, they simply become a and o, which is what a Swedish reader would expect.

Finally, transliterate itself. It's on by default, and turning it off changes behavior quite a bit. Non Latin letters are preserved rather than converted, so "Déjà Vu" becomes déjà dash vu, and Chinese or Arabic text stays as is. Internally the allowed character set expands to every Unicode letter and number, and the regex gets the Unicode flag. The readme mentions this can be faster when you don't need ASCII output. There's one subtle consequence worth remembering: the built in replacements for ampersand, heart and unicorn are not applied when transliteration is off. Your own custom replacements still are, through a simple loop of replace all calls. So an ampersand just disappears unless you add your own replacement for it.

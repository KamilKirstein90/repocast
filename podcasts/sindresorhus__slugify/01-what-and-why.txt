Welcome to this series, where we take one small but surprisingly clever JavaScript library and look at it from every angle: slugify, by Sindre Sorhus.

Let's start with the most basic question. What is a slug? If you have ever written a blog post and noticed that the title "My First Post!" turned into something like my dash first dash post in the address bar, you have seen a slug. A slug is a cleaned up version of a piece of text that is safe to use in a web address, in a filename, or as an identifier, for example as the ID of a heading in an HTML page so you can link straight to it. Slugs are lowercase, they replace spaces and punctuation with a separator, usually a dash, and they contain only plain, predictable characters.

That sounds trivial. You might think: I'll just lowercase the string, replace everything that isn't a letter or a digit with a dash, and be done. And for English text that works for about five minutes. Then someone writes a title in German with umlauts, or in Russian, or in Vietnamese, or puts an ampersand or an emoji in it, or writes an apostrophe in "Conway's Law", and suddenly your naive approach produces ugly slugs, empty slugs, or slugs with strange fragments like conway dash s dash law.

This library exists to handle all of those cases so you don't have to. You give it a string, and it gives you back a nice slug. "I love dogs" written with a heart symbol becomes i dash love dash dogs. "Déjà Vu" with accents and an exclamation mark becomes deja dash vu. A camel cased identifier like fooBar becomes foo dash bar. And a Russian sentence meaning "I love unicorns" becomes a readable Latin transcription instead of disappearing.

Who is it for? Pretty much any JavaScript or TypeScript developer who generates URLs, filenames, or anchor IDs from user supplied text. Think static site generators, documentation tools, content management systems, markdown renderers that need heading anchors, or any app that turns a title into a route. It runs on Node, it is published as a modern ES module, and because it has no side effects and no Node specific APIs in its core logic, it is also easy to bundle for the browser.

The main idea behind the library is a pipeline. The input string goes through a series of small, focused steps. First, special characters and non Latin letters are converted to plain Latin letters, a process called transliteration. Then camel case words are split apart. Then the text is lowercased, apostrophes in contractions are dropped, every run of unwanted characters is replaced with the separator, and finally leftover separators at the edges or doubled up in the middle are cleaned away. Each of those steps is small, but together they produce slugs that look like a human picked them.

Another important idea is that the heavy lifting of transliteration is not done in this repository at all. It is delegated to a sibling package from the same author called transliterate. That keeps slugify itself tiny. The whole core is a single file of roughly one hundred sixty lines. So this is a great repository to study if you want to see how a focused, well tested open source utility is put together, and how much thinking can go into something that looks simple from the outside.

There is also a second function in the package, called slugify with counter. It solves a related problem: what happens when two headings in the same document have the same title? You can't give two elements the same ID. The counter version remembers what it has already handed out and appends a number, so the second "Example" heading becomes example dash two. We will spend a whole episode on how that works, because it has some subtle edge cases.

The project is MIT licensed, it is currently at major version three, and it requires Node version twenty or newer.
